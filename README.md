# Port-checker

Десктопное приложение на Qt6/C++ для проверки конкретных портов ваших VPS. Раз в секунду проверяет доступность портов на заданных серверах через TCP-подключение, отображает статус, задержку и время последней проверки в таблице и хранит список хостов и историю проверок в PostgreSQL.

## Возможности

- Периодическая проверка доступности хостов (TCP connect) без блокировки GUI — раз в секунду
- Параллельные проверки через `QThreadPool` — все хосты проверяются одновременно, а не по очереди
- Список хостов хранится в PostgreSQL и полностью управляется из интерфейса: добавление и удаление хоста не требуют пересборки проекта
- Таблица с колонками: имя, адрес:порт, статус, задержка (мс), время последней проверки
- Сохранение каждого результата проверки в PostgreSQL (`metrics`) и отслеживание момента, с которого хост недоступен (`host_status.down_since`); если хост недоступен, задержка пишется как `0`
- Автоматическая очистка старых метрик по настраиваемому времени хранения (`clear_rules`) с переносом в архив (`archive`); также доступна ручная очистка `metrics`/`archive` из интерфейса
- Автоматическое переподключение к PostgreSQL при обрыве соединения

## Стек

- C++17
- Qt6 (Core, Widgets, Network, Sql)
- CMake ≥ 3.19
- PostgreSQL 18 (в Docker)

## Архитектура

Каждый цикл проверки создаёт по одному объекту `HostChecker` (`QObject` + `QRunnable`) на хост и отправляет их в `QThreadPool`. `HostChecker` выполняет `QTcpSocket::connectToHost` с таймаутом и по завершении эмитит сигнал `finished(FullInfo)`, который через queued-соединение долетает до GUI-потока и обновляет соответствующую строку таблицы. Объекты `HostChecker` одноразовые: `QThreadPool` удаляет их сам после `run()` (`autoDelete` по умолчанию `true`), новый набор создаётся заново на каждый тик — это снимает необходимость в ручном управлении временем жизни воркеров.

Вся работа с PostgreSQL вынесена в отдельный класс `DBService` (соединение, подготовленные запросы, транзакции). `MainWindow` не работает с `QSqlDatabase` напрямую, а вызывает методы `DBService` (`loadHosts`, `writeCheckResults`, `addHost`, `removeHost`, `runCleanup`, `deleteMetrics`, `deleteArchive`). Результат каждой проверки (`FullInfo`) уходит в БД через `writeCheckResults`, вызываемый из `onHostCheckerFinished` в GUI-потоке — запись метрики и обновление `host_status` идут в одной транзакции.

Если подключение к БД не установлено (при старте или обрывается в процессе работы), приложение не завершает работу — проверки хостов продолжаются, просто результаты не сохраняются. Отдельный `reconnectTimer` каждые `Config::reconnectTime` мс проверяет `db.isOpen()` и при разрыве пытается переподключиться и заново подготовить запросы; при успехе список хостов перечитывается из БД.

## Требования для подключения к PostgreSQL

Чтобы приложение на базе Qt могло подключаться к PostgreSQL, в системе должна присутствовать клиентская библиотека `libpq`.

**Windows:**

Проще всего — через обычный инсталлятор PostgreSQL (EnterpriseDB): при установке достаточно оставить компонент **Command Line Tools** (он включает `libpq`) и снять галку с самого сервера — поднимать локальный PostgreSQL не нужно. Останется добавить путь к папке `bin` (обычно `C:\Program Files\PostgreSQL\<версия>\bin`) в переменную среды `Path`.

Альтернативно можно обойтись без инсталлятора:

1. Скачайте ZIP-архив Binaries для Windows x86-64 с официальной страницы загрузок PostgreSQL.
2. Скопируйте из архива папку `bin`.
3. Добавьте путь к этой папке в системную переменную среды `Path`.

В обоих случаях перезапустите Qt Creator или терминал, чтобы программа увидела обновлённую переменную среды.

**Linux:**

Установите пакет `libpq-dev` (Debian/Ubuntu) или аналог из репозитория вашего дистрибутива.

## Сборка

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

Перед первым запуском поднимите базу данных (см. ниже) — без неё приложение просто продолжит работать без записи метрик и без списка хостов (см. «Переподключение» в архитектуре).

## База данных

PostgreSQL разворачивается в Docker через `docker-compose.yml`:

```bash
docker compose up -d
```

Поднимется контейнер `postgres-dev` (PostgreSQL 18) на порту `5432`, а `init.sql` при первом старте (пока том `postgres_data` пуст) автоматически создаст схему из пяти таблиц:

- `hosts` — список отслеживаемых хостов (`info`, `ip`, `port`), пара `ip`+`port` уникальна
- `host_status` — текущий статус хоста: `down_since` (когда хост стал недоступен, `NULL` — если всё в порядке)
- `metrics` — история проверок по каждому хосту: статус, задержка, время
- `clear_rules` — время хранения метрик для каждого хоста (`retain_for`, по умолчанию 30 секунд)
- `archive` — метрики, вынесенные из `metrics` после истечения `retain_for`; хранит `info`/`ip`/`port` как есть, без внешнего ключа — переживает удаление хоста

Полная схема, включая внешние ключи и `CASCADE`-удаление — в `init.sql`.

Параметры подключения (хост, порт, имя БД, пользователь, пароль) захардкожены в неймспейсе `Config` (`common/Common.h`) и должны совпадать с `docker-compose.yml` (по умолчанию — `postgres`/`postgres`/`mysecretpassword`). Меняете пароль или порт в `docker-compose.yml` — поправьте и `Config` в `Common.h`.

## Управление списком хостов

Список хостов хранится в таблице `hosts` в PostgreSQL и управляется прямо из интерфейса приложения:

- **addHost** — открывает диалог с полями Info/Ip/Port и добавляет новый хост в БД
- **deleteHost** — удаляет выбранный в таблице хост; связанные записи в `host_status`, `metrics` и `clear_rules` удаляются каскадно

Изменение списка хостов не требует пересборки проекта — новый хост появляется в таблице сразу после добавления.

## Очистка данных

- Раз в `Config::cleanupTime` мс приложение автоматически переносит в `archive` метрики, устаревшие согласно `clear_rules.retain_for`, и удаляет их из `metrics`
- **clearMetrics** — вручную очищает таблицу `metrics` (перед удалением так же переносит данные в `archive`)
- **clearArchive** — вручную очищает таблицу `archive`

## Настройки (`common/Common.h`, namespace `Config`)

| Параметр | Смысл |
|---|---|
| `threadsCount` | размер `QThreadPool` — сколько хостов проверяется одновременно |
| `delay` | интервал проверки хостов, мс |
| `cleanupTime` | интервал автоматического переноса устаревших метрик в архив, мс |
| `reconnectTime` | интервал проверки соединения с БД и попытки переподключения, мс |

## Структура проекта

```
gui/                  MainWindow (UI-логика, таблица, таймеры, диалог добавления хоста)
hostchecker/          HostChecker (воркер для TCP-проверки одного хоста)
db/                    DBService (соединение с PostgreSQL, подготовленные запросы, транзакции, переподключение)
common/                общие структуры данных (BaseInfo/FullInfo) и Config
docker-compose.yml    контейнер PostgreSQL для хранения хостов и метрик
init.sql              схема БД (hosts, host_status, metrics, clear_rules, archive), применяется при первом старте контейнера
```
