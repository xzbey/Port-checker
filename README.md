# Port-checker

Десктопное приложение на Qt6/C++ для проверки конкретных портов ваших VPS. Раз в секунду проверяет доступность портов на заданных серверах через TCP-подключение, отображает статус, задержку и время последней проверки в таблице и хранит список хостов и историю проверок в PostgreSQL.

## Возможности

- Периодическая проверка доступности хостов (TCP connect) без блокировки GUI — раз в секунду
- Параллельные проверки через `QThreadPool` — все хосты проверяются одновременно, а не по очереди
- Список хостов хранится в PostgreSQL и полностью управляется из интерфейса: добавление и удаление хоста не требуют пересборки проекта
- Таблица с колонками: имя, адрес:порт, статус, задержка (мс), время последней проверки
- Сохранение каждого результата проверки в PostgreSQL (`metrics`) и отслеживание момента, с которого хост недоступен (`host_status.down_since`); если хост недоступен, задержка пишется как `0`
- Автоматическая очистка старых метрик по настраиваемому для каждого хоста времени хранения (`clear_rules`) с переносом в архив (`archive`); также доступна ручная очистка `metrics`/`archive` из интерфейса
- Изменение времени хранения метрик выбранного хоста прямо из интерфейса
- Просмотр содержимого любой из таблиц БД во встроенном диалоге
- При удалении хоста его метрики не пропадают, а переносятся в архив
- Автоматическое переподключение к PostgreSQL при обрыве соединения

## Стек

- C++17
- Qt6 (Core, Widgets, Network, Sql)
- CMake ≥ 3.19
- PostgreSQL 18 (в Docker)

## Интерфейс

Главное окно состоит из таблицы хостов и панели кнопок под ней. Кнопки сгруппированы в блоки, у каждого есть подпись с описанием действия:

| Кнопка | Действие |
|---|---|
| `addHost` | добавить новый хост |
| `deleteHost` | удалить выбранный хост |
| `selectTable` | выбрать и посмотреть таблицу БД |
| `changeClearRules` | изменить время хранения метрик выбранного хоста |
| `clearMetrics` | очистить таблицу `metrics` |
| `clearArchive` | очистить таблицу `archive` |

Кнопки `deleteHost` и `changeClearRules` работают с хостом, выбранным в таблице (выделяется строка целиком).

## Архитектура

Каждый цикл проверки создаёт по одному объекту `HostChecker` (`QObject` + `QRunnable`) на хост и отправляет их в `QThreadPool`. `HostChecker` выполняет `QTcpSocket::connectToHost` с таймаутом и по завершении эмитит сигнал `finished(FullInfo)`, который через queued-соединение долетает до GUI-потока и обновляет соответствующую строку таблицы. Объекты `HostChecker` одноразовые: `QThreadPool` удаляет их сам после `run()` (`autoDelete` по умолчанию `true`), новый набор создаётся заново на каждый тик — это снимает необходимость в ручном управлении временем жизни воркеров.

Вся работа с PostgreSQL вынесена в отдельный класс `DBService` (соединение, подготовленные запросы, транзакции). `MainWindow` не работает с `QSqlDatabase` напрямую, а вызывает методы `DBService`:

- `loadHosts`, `addHost`, `removeHost` — управление списком хостов
- `writeCheckResults` — запись результата проверки
- `runCleanup`, `deleteMetrics`, `deleteArchive` — очистка данных
- `updateClearRules` — изменение времени хранения метрик хоста
- `getModel` — модель для просмотра таблицы
- `isOpen`, `reconnect` — состояние соединения и переподключение

Результат каждой проверки (`FullInfo`) уходит в БД через `writeCheckResults`, вызываемый из `onHostCheckerFinished` в GUI-потоке — запись метрики и обновление `host_status` идут в одной транзакции. Все обращения к БД выполняются только из GUI-потока, соединение между потоками не разделяется.

Если подключение к БД не установлено при старте, список хостов остаётся пустым: приложение не завершает работу и ждёт, пока `reconnectTimer` сможет подключиться, после чего список читается из БД. Если соединение обрывается во время работы, проверки хостов продолжаются, просто результаты не сохраняются. Обрыв обнаруживается при неудачной записи метрики, после чего `reconnectTimer` каждые `Config::reconnectTime` мс проверяет `db.isOpen()` и пытается переподключиться и заново подготовить запросы; при успехе список хостов перечитывается из БД.

## Требования для подключения к PostgreSQL

Чтобы приложение на базе Qt могло подключаться к PostgreSQL, в системе должна присутствовать клиентская библиотека `libpq`.

**Windows:**

Проще всего — через обычный инсталлятор PostgreSQL (EnterpriseDB): при установке достаточно оставить компонент **Command Line Tools** (он включает `libpq`) и снять галку с самого сервера — поднимать локальный PostgreSQL не нужно. Останется добавить путь к папке `bin` (обычно `C:\Program Files\PostgreSQL\<версия>\bin`) в переменную среды `Path`.

Альтернативно можно обойтись без инсталлятора:

1. Скачайте ZIP-архив Binaries для Windows x86-64 с официальной страницы загрузок PostgreSQL.
2. Скопируйте из архива папку `bin`.
3. Добавьте путь к этой папке в системную переменную среды `Path`.

В обоих случаях перезапустите Qt Creator или терминал, чтобы программа увидела обновлённую переменную среды.

**Linux:**

Установите пакет `libpq-dev` (Debian/Ubuntu) или аналог из репозитория вашего дистрибутива.

## Сборка

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

Перед первым запуском поднимите базу данных (см. ниже) — без неё приложение запустится, но список хостов будет пуст и метрики писаться не будут (см. «Архитектура» про переподключение).

## База данных

PostgreSQL разворачивается в Docker через `docker-compose.yml`:

```bash
docker compose up -d
```

Поднимется контейнер `postgres-dev` (PostgreSQL 18) на порту `5432`, а `init.sql` при первом старте (пока том `postgres_data` пуст) автоматически создаст схему из пяти таблиц:

- `hosts` — список отслеживаемых хостов (`info`, `ip`, `port`), пара `ip`+`port` уникальна
- `host_status` — текущий статус хоста: `down_since` (когда хост стал недоступен, `NULL` — если всё в порядке)
- `metrics` — история проверок по каждому хосту: статус, задержка, время
- `clear_rules` — время хранения метрик для каждого хоста (`retain_for`, по умолчанию 30 секунд)
- `archive` — метрики, вынесенные из `metrics` (по истечении `retain_for`, при ручной очистке или при удалении хоста); хранит `info`/`ip`/`port` как есть, без внешнего ключа — переживает удаление хоста

Полная схема, включая внешние ключи и `CASCADE`-удаление — в `init.sql`.

Если нужно изменить схему, учтите: `init.sql` выполняется только на пустом томе. Чтобы применить новую версию, удалите том командой `docker compose down -v` (данные при этом будут потеряны).

Параметры подключения (хост, порт, имя БД, пользователь, пароль) захардкожены в неймспейсе `Config` (`common/Common.h`) и должны совпадать с `docker-compose.yml` (по умолчанию — `postgres`/`postgres`/`mysecretpassword`). Меняете пароль или порт в `docker-compose.yml` — поправьте и `Config` в `Common.h`.

## Управление списком хостов

Список хостов хранится в таблице `hosts` в PostgreSQL и управляется прямо из интерфейса приложения:

- **addHost** — открывает диалог с полями Info/Ip/Port и добавляет новый хост в БД
- **deleteHost** — удаляет выбранный в таблице хост. Перед удалением все метрики хоста переносятся в `archive` (одним запросом, в одной транзакции с удалением), связанные записи `host_status` и `clear_rules` удаляются каскадно

Изменение списка хостов не требует пересборки проекта — новый хост появляется в таблице сразу после добавления.

## Очистка данных и время хранения метрик

- Раз в `Config::cleanupTime` мс приложение автоматически переносит в `archive` метрики, устаревшие согласно `clear_rules.retain_for`, и удаляет их из `metrics`
- **changeClearRules** — задаёт время хранения метрик для выбранного в таблице хоста. В диалоге вводятся часы, минуты и секунды (максимум `23:59:59`); значение `0:0:0` не принимается. Новое время применяется только к этому хосту
- **clearMetrics** — вручную очищает таблицу `metrics` (перед удалением так же переносит данные в `archive`)
- **clearArchive** — вручную очищает таблицу `archive`

## Просмотр таблиц

Кнопка **selectTable** открывает диалог выбора одной из таблиц БД (`hosts`, `host_status`, `metrics`, `clear_rules`, `archive`), после чего содержимое выбранной таблицы показывается в отдельном окне только для чтения. Данные загружаются в момент открытия окна и автоматически не обновляются — чтобы увидеть свежие значения, окно нужно открыть заново.

## Настройки (`common/Common.h`, namespace `Config`)

Основные параметры приложения собраны в неймспейсе `Config` в файле `common/Common.h`. Они задаются при сборке, поэтому после изменения любого из них проект нужно пересобрать.

**Подключение к БД** (должны совпадать с `docker-compose.yml`):

| Параметр | Смысл |
|---|---|
| `dbType` | драйвер Qt для работы с БД (`QPSQL` для PostgreSQL) |
| `ip` | адрес сервера PostgreSQL |
| `port` | порт сервера PostgreSQL |
| `dbName` | имя базы данных |
| `userName` | пользователь БД |
| `password` | пароль пользователя БД |

**Работа приложения:**

| Параметр | Смысл |
|---|---|
| `threadsCount` | размер `QThreadPool` — сколько хостов проверяется одновременно |
| `delay` | интервал проверки хостов, мс |
| `cleanupTime` | интервал автоматического переноса устаревших метрик в архив, мс |
| `reconnectTime` | интервал проверки соединения с БД и попытки переподключения, мс |

```
gui/                  MainWindow (UI-логика, таблица, таймеры, диалоги: добавление хоста,
                      время хранения метрик, выбор и просмотр таблицы)
hostchecker/          HostChecker (воркер для TCP-проверки одного хоста)

                      переподключение, модель для просмотра таблиц)

```
