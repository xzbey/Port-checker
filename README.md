# VPN-Watcher

Десктопное приложение на Qt6/C++ для проверки состояния хостов VPN-инфраструктуры или проще — проверка конкретных портов ваших VPS. Раз в секунду проверяет доступность портов на заданных серверах через TCP-подключение, отображает статус, задержку и время последней проверки в таблице и сохраняет каждую проверку в PostgreSQL.

## Возможности

- Периодическая проверка доступности хостов (TCP connect) без блокировки GUI
- Параллельные проверки через `QThreadPool` — все хосты проверяются одновременно, а не по очереди
- Список хостов задаётся конфигом в JSON
- Таблица с колонками: имя, адрес:порт, статус, задержка (мс), время последней проверки
- Сохранение каждого результата проверки в PostgreSQL (таблица `metrics`); если хост недоступен, задержка пишется как `0`

## Стек

- C++17
- Qt6 (Core, Widgets, Network, Sql)
- CMake ≥ 3.19
- PostgreSQL 18 (в Docker)

## Архитектура

Каждый цикл проверки создаёт по одному объекту `HostChecker` (`QObject` + `QRunnable`) на хост и отправляет их в `QThreadPool`. `HostChecker` выполняет `QTcpSocket::connectToHost` с таймаутом и по завершении эмитит сигнал `finished(FullInfo)`, который через queued-соединение долетает до GUI-потока и обновляет соответствующую строку таблицы. Объекты `HostChecker` одноразовые: `QThreadPool` удаляет их сам после `run()` (`autoDelete` по умолчанию `true`), новый набор создаётся заново на каждый тик — это снимает необходимость в ручном управлении временем жизни воркеров.

Тот же результат проверки (`FullInfo`) параллельно уходит в PostgreSQL через подготовленный `INSERT`-запрос (`QSqlQuery`), выполняемый в GUI-потоке из `onHostCheckerFinished`. Если соединение с БД на старте не установилось, приложение продолжает работать и просто не пишет в базу (флаг `dbReady`).

## Требования для подключения к PostgreSQL

Чтобы приложение на базе Qt могло подключаться к PostgreSQL, в системе должна присутствовать клиентская библиотека `libpq`.

**Windows:**

1. Скачайте ZIP-архив Binaries для Windows x86-64 с официальной страницы загрузок PostgreSQL (EnterpriseDB).
2. Скопируйте из архива папку `bin`.
4. Добавьте путь к этой папке в системную переменную среды `Path`.
5. Перезапустите Qt Creator или терминал, чтобы программа увидела обновлённую переменную среды.

**Linux:**

Установите пакет `libpq-dev` (Debian/Ubuntu) или аналог из репозитория вашего дистрибутива.

## Сборка

```bash
mkdir build && cd build
cmake ..
cmake --build .
```

Перед первым запуском поднимите базу данных (см. ниже) — без неё приложение просто продолжит работать без записи метрик.

## База данных

PostgreSQL разворачивается в Docker через `docker-compose.yml`:

```bash
docker compose up -d
```

Поднимется контейнер `postgres-dev` (PostgreSQL 18) на порту `5432`, а `init.sql` при первом старте (пока том `postgres_data` пуст) автоматически создаст таблицу `metrics`:

```sql
CREATE TABLE metrics(
    metrics_id SERIAL PRIMARY KEY,
    info TEXT NOT NULL,
    ip INET NOT NULL,
    port INT NOT NULL CHECK (port BETWEEN 1 AND 65535),
    status BOOL NOT NULL,
    latency BIGINT,
    ts TIMESTAMPTZ DEFAULT (now() AT TIME ZONE 'Europe/Moscow')
);
```

Параметры подключения (хост, порт, имя БД, пользователь, пароль) сейчас захардкожены в конструкторе `MainWindow` и должны совпадать с `docker-compose.yml` (по умолчанию — `postgres`/`postgres`/`mysecretpassword`). Меняете пароль или порт в `docker-compose.yml` — поправьте и вызов `createDbConnection` в коде.

## Конфигурация

Список хостов хранится в `common/list.json` и на этапе сборки встраивается в бинарник через Qt Resource System (`common/resources.qrc`). Изменение списка требует пересборки проекта.

Формат:

```json
[
    {
        "info": "XRay Country1",
        "ip": "1.1.1.1",
        "port": "443"
    }
]
```

- `info` — отображаемое название сервиса
- `ip` — IPv4-адрес хоста
- `port` — TCP-порт (строкой)

## Структура проекта

```
gui/                  MainWindow (UI-логика, таблица, таймер, запись в БД)
hostchecker/          HostChecker (воркер для TCP-проверки одного хоста)
common/                общие структуры данных (BaseInfo/FullInfo) и конфиг
docker-compose.yml    контейнер PostgreSQL для хранения метрик
init.sql              схема таблицы metrics, применяется при первом старте контейнера
```
